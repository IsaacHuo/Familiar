Last reviewed: 2026-10-04. B1/B2/B3/C1–C9/D/E1/E4/E5/E6/F1–F5 implementation/source review, static checks and arm64 test-target compilation are verified. Three Node renderer scheduling cases executed; iOS tests and real-service/device acceptance remain pending.

## Current Focus

Familiar is converging around native iPhone Chat, long-lived Project context and one Agent Runtime. The cross-chat implementation and acceptance ledger is [PLAN.md](../PLAN.md).

The target Harness is **One Agent + One Loop + Lazy Tools + Progressive Escalation**. Stability and product logic precede the full-app visual pass. OpenMinis is a reference, not a parity target. No task-complexity Router, fixed planning pipeline, new orchestration kernel, background execution or cross-restart continuation is being added.

Completed B1 removes mandatory planning. Project and Daily Chat can now return an answer on their first model request without task_plan or unrelated tool evidence. task_plan is an optional display checklist. The loop no longer withholds answer text to force a plan, enforces ordered step completion, binds publication to a promised deliverable ID, runs automatic delivery repair, or persists duplicate execution-state snapshots. Actual tool/approval/result boundaries and the single runFinished outcome remain.

B2 now separates the frozen permitted catalog from the current model request. The initial request exposes only current_date_time, ask_user and tools_load. The model selects at most two extension groups; each successful load replaces the active extension schemas. Guessed/unexposed names fail without execution, including when batched with a loader. Project and Skill scopes share one base-tool rule, permissions remain checked at execution, and attempted calls consume the Run budget.

Native group metadata carries no full schemas. HTTP MCP discovery runs only when an enabled server group is requested, caches that Run's definitions, pages descriptions and requires exact tool selection before exposing remote schemas. Selected manifests are persisted at the success boundary. iSH is not prepared at App startup: actual Shell/Environment operations prepare it on demand. Shared preparation has cancellable waiters; cancelling a Run does not stop private shared setup, but prevents that Run from starting its command. Real guest behavior is still unaccepted.

C2 now journals committing invocations before action calls and reserves exact write fingerprints at that point. Failed or uncertain writes cannot be blindly replayed in the same Run; interrupted journals stay uncertain. Necessary outputs and durable Undo are saved before success events. Local rollback/finalize hooks compensate new Artifact bytes and Environment swaps; external writes are never silently undone.

Artifact edit now creates an independent successor version instead of replacing old bytes. Artifact deletion/Undo stages the directory until the metadata save succeeds. Undo results are cached through save retries, and native durable Undo is marked unavailable before action so a crash does not cause automatic replay. Editing/regenerating a history segment with committed/uncertain actions is blocked, preserving receipts; pure read history remains regenerable.

C3 now prepares and validates the frozen input before inserting the conversation, user message or committed attachment files. Protected Project input, the pending turn and base schemas must fit together; old history remains eligible for automatic compaction. Vision evidence is checked again before submission, and supported image input fails explicitly when bytes cannot be read. Only a successful submission save consumes the draft; the same validated snapshot enters the Run. C7 uses read-only keyword candidates and stages lastUsedAt only for memories admitted by the compiler, in the accepted message save.

C4 now keeps fetched pages in the existing persisted tool envelope, including the exact capture time and body hash. The old transient webCaptures channel and Controller auto-import are removed. Expanding a successful web_fetch result offers Save to Project, which resolves the owning Project and captured bytes from the persisted result. It performs no network fetch, verifies integrity, and deduplicates repeat saves. Saved text includes URL/time/source ID/body hash/truncation provenance alongside its body, so future Project input retains the partial-page boundary. Existing Resources are retained; older results without complete capture metadata do not offer this action.

B3 removes the unused CapabilityCatalog/Resolver/Binding and Grant issuance/consumption APIs. Canonical argument hashing now has no Grant dependency. The selected Provider (including a user-configured model group) feeds the one Loop directly; the unfinished local/cloud Router, escalation coordinator/observer/dialog and obsolete route setting are removed. AuthorizationRuleRecord is the only active persisted authorization contract: matching requires exact scope, rejects invalid durations and propagates lookup/save failures; failed consumption/issuance saves roll back before any effect. Historical Grant columns remain inert audit data in the unchanged 37-entity schema, with no signing or consuming runtime path.

C5 verifies the current default text-delivery boundary: artifact_write/edit/read are enabled by default, while workspace_write, artifact_publish and Shell/Environment preparation require explicit capability configuration. The policy now prefers direct replies and Markdown/plain text when file delivery is requested; text writes reject complex formats before approval or bytes. Real guest/complex-file acceptance remains separate.

C8 uses the same effective Project model resolution for the top bar, credential affordance and send. A pinned Project model is changed in Project scope; the menu can restore the default. Opening history no longer changes the default to historical model metadata. Standalone adapters emit request identity and groups suppress duplicate member identity. Response messages store the final actual member; Run snapshots retain the original requested group/model, and regeneration uses that original selection. Recorder stores ordered attempted models and reported nullable usage. Automatic compaction now forwards identity and usage into the same Run; manual compaction/provider setup remain outside these totals and are explicitly described. Partial run totals are labeled, not filled with estimates.

C9 centralizes credential lookup in ProviderFactory: group availability requires a real credentialed member, not an arbitrary group key. Configuration, send/manual-compaction guards and member construction use that rule; submission rechecks credentials before committing. Cancelled document imports check after conversion and delivery, removing only their owned draft. Attachment commits reject existing destinations and preserve previously committed bytes on collisions. View reappearance cannot recover live sends/compactions or prune their temporary files.

F1 inventories all current tests: 41 Simulator suites, two separately selected signed-device suites and the full UI-test target. The release script checks omissions/duplicates/stale entries and reads actual xcresult summary counts; zero tests, skips, expected failures and missing counts prevent a pass claim. The Keychain-dependent image scenario is now a separate signed queued-cancellation test; no signing entitlement causes failure instead of an assertion-free unverified success. It claims neither OCR nor provider execution. No test run was performed in this slice.

D1.1-D1.4 now group navigation around Chat and Project context. Chat has no Diagnostics shortcut. Project exposes New Chat as its visible main action, with instructions/chats/resources/outputs and one Advanced link; Environment/Skills/MCP/Capabilities/Run history live there. Settings has Models & Responses, Appearance, Privacy & Data, and Support; optional execution/integrations/model groups and troubleshooting use Advanced. Memory and approved-action revocation remain direct entries. Model-service configuration no longer edits or adds voice providers; Voice settings is the sole management entry. Stored providers, keys, Project bindings and old destinations are retained. D1.5/D2/D3 implementation is now complete: shared semantic fonts/metrics, icon targets/feedback, identity-driven previews, common modal closing, readable file approval and localizable receipts/errors, and native renderer styling are connected. The fixture uses the production execution blocks; its obsolete ToolChips tree is removed. Device acceptance remains separate.

SurfaceStore ignores events with no presentation effect before observable mutation. History Run lookup uses a render-local index rather than scanning every Run for each row; history still uses eager VStack and no persistent cache. Image preparation runs concurrently off MainActor with cancellation checks and owned-file cleanup; formal submission checks remain on MainActor.

The bundled renderer keeps 80ms streaming coalescing and immediate terminal rendering. A render version now drops stale Mermaid success/failure/decoration and stops scheduling obsolete remaining diagrams. Three scheduling tests passed in Node using a limited DOM double; old-source control failed all three. This is not real Mermaid/WebKit layout, SVG-security, UI or performance acceptance. Unified owner steps are in [docs/15-owner-device-acceptance.md](../docs/15-owner-device-acceptance.md).

## Implemented Paths

- Chat: direct launch, protected Daily Chat Project, drafts and attachments, editable speech transcription, streaming text/reasoning, ordered Markdown/tool blocks, approval/clarification, cancellation, local history, retry, manual compaction, branching, project move and text export.
- Models: local Provider instances and independent Keychain identities, four text wire protocols, Kimi Code/Codex/OpenRouter sign-in implementations, model groups and reported usage. The catalog is no longer DeepSeek-only. No Familiar account or hosted backend exists.
- Project: instructions, optional model override, versioned files/web/text Resources, frozen ContextSnapshot, conversations and Artifact history. Chat remains the execution entry.
- Tools: typed manifests, capability availability, scoped authorization, structured proposals/results, read-only Web, EventKit, native adapters, controlled Workspace/Shell and Artifact output. A model cannot authorize its own actions.
- Memory: global/project/conversation records, user-confirmed remember proposals, frozen-search selection, budgeted Context Compiler injection and Settings management. Approved memory is persisted through the Run commit callback before success events; save failure becomes a tool failure.
- Skills: instruction selection and scope narrowing, Project binding, checked immutable package preparation/import with SKILL.md and hashed resources. Resource packages do not grant native permissions or automatically run installation scripts. Real package/guest tasks are unverified.
- MCP: Lazy HTTP discovery and approved calls, per-run registry snapshot, conversation/project/global bindings. STDIO, OAuth and full Schema coverage are unfinished.
- Artifact: text writes, readback, real-file signature/content/hash validation and publication, lineage/version lists, Quick Look and sharing. Publication no longer requires a task_plan; optional requiredText/minimumSources checks are supplied on the publish call itself.
- Environment: bundled iSH/Alpine, preparation lifecycle, Project Workspace mounts, dependency preparation, bounded output/network/resource policy, checkpoints and on-demand shared preparation. Guest operation is not accepted on a physical device.
- UI: semantic Theme/Typography/Spacing/Radius/Motion and availability-gated native glass. D component/page implementation is complete; physical-device visual/accessibility acceptance remains pending.

## Known Problems

1. **Harness acceptance remains**: unused Capability/Grant and local/cloud routing paths are removed. Real-model lazy group selection, fallback, cancellation and signed-store authorization failures still need acceptance. Character budgeting includes parameter schemas and load reports, but remains a character estimate, not tokenizer accounting. Historical Grant audit columns remain stored; they confer no authority and no automatic data/schema cleanup is claimed.
2. **Crash windows remain unaccepted**: pre-action journals, persistence gating, local compensation and Undo caching are implemented. A process exit immediately after an external effect can still leave an uncertain journal without a full receipt; it blocks blind regeneration, not the original effect. Native permissions, disk-full and process-kill boundaries remain device-unverified.
3. **Web retention acceptance remains**: ordinary fetches no longer create Resources. Explicit saving and repeat-save integrity checks are implemented; real network/physical-device UI acceptance is still missing. Previously imported Resources remain, and all explicitly retained Project input still consumes the protected context budget.
4. **Submission acceptance is not Provider acceptance**: local preflight and save failures now retain the draft, but later network/Provider/compaction failures can still occur after an accepted message. Budgeting is a local character estimate; signed-device draft cancellation, Vision and storage-failure behavior remain unverified.
5. **Artifact acceptance**: edit and publish now use independent versions and local deletion compensation. Version browsing, sharing, Undo and filesystem/database recovery still lack device/visual acceptance.
6. **Design acceptance remains**: D implementation and build/static work is complete. `docs/14-design-system-device-acceptance.md` lists the unresolved physical-device checks for navigation, maximum text size, VoiceOver, contrast, reduced motion/transparency, small screens and keyboard. No visual/accessibility runtime pass is inferred from compilation.
7. **No cross-restart execution**: cursor/invocation records are audit data; startup ends interrupted runs and pending interactions. Do not advertise paused/resumable execution. Reliable background execution is absent.
8. **Acceptance gaps**: real Provider authentication/stream/tools/cancellation, DuckDuckGo/network behavior, MCP servers, system permissions, iSH, complex documents, speech, Face ID and device visual/accessibility behavior remain unaccepted in this review.
9. **Test execution remains pending**: current inventory is complete and checked before script execution. Simulator suites exclude signed-only image and real guest tests; device suites are opt-in. The script rejects zero/skipped/expected-failure results, but no current suite execution is claimed by compilation or inventory checks.
10. Keychain coverage is unavailable in unsigned hosts when SecItem returns errSecMissingEntitlement. Signed-only tests fail that prerequisite rather than silently passing. Store damage, disk-full, real Vision and signed upgrade behavior still require device checks.
11. Core AI is an unavailable adapter contract; FamiliarMac is a separate shell without the shared iOS execution/data path. Neither is part of this convergence acceptance.
12. E5 voice/OAuth warnings are fixed and relevant sources compiled without those Swift warnings. Real sign-in/callback/refresh and speech behavior remain unaccepted. E2/E3 still need device measurements for eager history/WebKit count, large Markdown/layout/memory; no measured performance gain or lazy-layout decision is claimed.
